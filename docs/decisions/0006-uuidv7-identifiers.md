# ADR 0006: Time-ordered UUID identifiers

- Status: Accepted
- Date: 2026-09-21
- Supersedes: None
- Superseded by: None

## Context

Domain IDs were random UUIDs while the auth library generated opaque text IDs. As relationships grow, the project needs one time-ordered identifier strategy for every generated entity.

## Goal

Every generated entity ID, auth and domain alike, is a time-ordered UUID (UUIDv7) from a single generator. Provider-issued identifiers stay opaque.

## Decision

- Auth user, session, account, and verification IDs and all domain IDs are UUIDv7, generated by one shared generator.
- IDs and foreign keys are stored as native database UUIDs; at application boundaries they are canonical UUID strings.
- Provider identifiers (such as the GitHub account ID), session tokens, and verification identifiers/values are opaque text, not UUIDs.
- Database defaults must not generate random UUIDs for entity IDs.

## Consequences

Auth and domain creation share one generator, so IDs sort by creation time. Future migrations must use UUID-compatible IDs and foreign keys.

## Implementation notes (non-binding)

- Generator: `server/utils/id.ts` using the `uuid` package's `v7()`; wired into Better Auth via `advanced.database.generateId` in both production and test auth configs; Drizzle `uuid()` columns.

## Alternatives considered

- Auth library's built-in UUID option: generates UUIDv4.
- Database `gen_random_uuid()` defaults: generate UUIDv4.
- Node's native UUIDv7: was not exposed by the installed type declarations; revisit if that changes.
