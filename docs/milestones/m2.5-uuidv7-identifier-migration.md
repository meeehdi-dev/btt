# M2.5 — UUIDv7 identifier migration

## Context

M2 currently creates domain IDs with `crypto.randomUUID()` (UUIDv4), while Better Auth generates its own text IDs. Before more product tables and relationships are added in M3, the project should decide whether all application and Better Auth identifiers should use UUIDv7 for time-ordered identifiers and establish one consistent generation boundary.

This milestone is a planning placeholder only. No UUID migration or ID-generation change is implemented by the M2 follow-up.

## Approved scope

Pending a separately approved milestone plan.

Proposed scope:

- Decide the canonical UUIDv7 representation and PostgreSQL column strategy.
- Inventory and migrate existing Better Auth and product-domain IDs, including every foreign key and persisted relation.
- Configure or wrap Better Auth ID generation so user, session, account, and verification records follow the decision where supported.
- Replace domain `crypto.randomUUID()` creation paths with the approved UUIDv7 generator.
- Define rollback/backfill safety, test fixtures, migration ordering, and deployment procedure.

## Out of scope

- Implementing the migration before plan approval.
- Changing product behavior or archive semantics.
- Adding tickets or time entries.
