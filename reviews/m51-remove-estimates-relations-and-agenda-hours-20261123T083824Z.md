### Verified without findings

- **Migration 0012 vs schema vs snapshot.** `drizzle/0012_slim_slipstream.sql` drops `ticket_relation` (CASCADE), `ticket_estimate_positive_check`, and `ticket.estimate_minutes`. A JSON diff of `drizzle/meta/0011_snapshot.json` → `0012_snapshot.json` shows exactly those removals (column, check, table with its indexes/FKs/check), with `prevId` chaining to 0011's `id`. `server/db/schema.ts` matches (no `estimateMinutes`, no `ticketRelation`, removed from `appSchema`; `check`, `sql`, `integer` still used by other tables). `_journal.json` idx 12 tag matches the file. The leading `DISABLE ROW LEVEL SECURITY` is drizzle-kit's standard output and harmless. I did not run the migration (no DB changes, per task); Build records a run on a disposable container.
- **Leftover code.** `rg -i "estimate_?minutes|ticket_?relation|relatedTicket|usageColor|parseTicketEstimate|parse-duration|showPercentage|completionBounds|related-hover|related-click|data-related"` outside `drizzle/`, `docs/milestones/`, `plans/`, `reviews/`, `.claude/` only hits ADR 0008/0067 history text. Remaining `estimate` hits in code are the `Estimate` status and `formatTicketEstimate` (kept by plan). No `.related` consumers remain after the ticket GET `related` field removal. `parse-duration-ms` removal touched only its own lockfile entries.
- **Filtered hours vs occupied.** `agenda.vue:934-935` passes `:rows="filtered"` (filtered from `activeEntries`) and `:occupied="weekAgenda?.entries ?? []"`. `WeeklyAgenda.vue` builds `trackedMinutesByDate` from `props.rows` only; every overlap/drag/hidden-row path (`:80, 196, 205, 233, 260, 367`) still reads `occupied`. With no filter, `filtered === entries`, so values equal the old server totals (same sum over the same entries). Target and overtime colors unchanged.
- **formatHours.** `${Number((minutes / 60).toFixed(1))}h`: 0→`0h`, 270→`4.5h`, 420→`7h`, 570→`9.5h`, 1440→`24h`. Time entries are 30-minute multiples (`shared/time-entry.ts:16-24`), so the hour value is always an exact .0/.5 and `toFixed` rounding never applies. A day sum above 24h cannot occur (no overlaps, one date). Negative input is impossible.
- **Release prefill.** `filters.release` is `''` when unset (`agenda.vue:117-122`); `TicketCreateModal`/`TicketCreateForm` both default `initialReleaseId` to `''` and treat falsy as "no prefill" (`TicketCreateForm.vue:44-53`). Tickets page passes `undefined`, which the default also maps to `''`. Both work. Selecting a ticket filter also sets `filters.release` (`useHierarchyFilters.ts:73`), so it prefills that ticket's release, which is reasonable.
- **Invalidation.** `TicketCreateModal.onTicketCreated` calls `invalidateMutation('ticket')`; `app/utils/app-data-resources.ts:5` maps it to `tickets, releases, time-entries, hierarchy, agenda, search`. The Agenda's `/api/tickets` read (`agenda.vue:101-104`) subscribes to `tickets`, and the week read subscribes to `agenda`/`tickets`. The new ticket reaches Add-work choices and filter options.
- **Accessibility of hours.** The `Nh` span is `aria-hidden`; the progressbar keeps its `aria-label`, `aria-valuemin/max`, `aria-valuenow` (filtered, capped at target) and `aria-valuetext` (filtered, with overtime), and the tooltip uses the same text. No duplicate announcement. `text-muted` at `text-xs` follows the existing muted-text convention (ADR 0049); I did not measure contrast.
- **Reports.** The period query (`server/domain/reports.ts:207-220`) is unchanged: same CTE join, filters, range and `trackedInRange` sums. Removing the cohort only removed the estimate query, the cohort `union` arm of the path query, and the `estimate` row field. Side effect, correct: filter-path options no longer include hierarchy that only had a Done-estimate cohort and no time in range. `getReportCompletionBounds` had no other callers; `resolveReportTimeZone` still validates the required time zone, so ADR 0061's 400-on-invalid-zone rule holds. `timeZone` is still echoed in the response. The `@internationalized/date` import removed from `shared/report-period.ts` is still a used dependency elsewhere (`check:unused` passes).
- **jscpd baseline.** Re-running `jscpd --baseline <HEAD baseline> --fail-on-new-clones 0` on the working tree reports 3 "new" clones: `api/search.get.ts`↔`domain/tickets.ts` (both untouched files), `api/tickets/index.get.ts`↔`domain/tickets.ts` (unchanged join boilerplate), and the `ticketLink` select in `api/tickets/index.get.ts`↔`domain/agenda.ts`. The last pair existed before the diff (both files had this exact select at HEAD); only its fingerprint changed because the surrounding relation code was deleted. No genuinely new duplication was hidden. The baseline went from 117 to 28 fingerprints, dropping stale ones.
- **Ticket ordering (R2).** `server/api/tickets/index.get.ts:47` is `desc(createdAt), desc(id)`; ADR 0028 matches.
- **ADR 0067** is consistent with 0007, 0018, 0028, 0039, 0061 and PLAN.md. Only 0012/0029 (R1) and the R2/R3 files disagree.
