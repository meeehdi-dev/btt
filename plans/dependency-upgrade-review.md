## Context

The user asked for a risk review of every open PR at [nxmr/pulls](https://github.com/meeehdi-dev/nxmr/pulls), including changelog review, and a staged recommendation for what to upgrade or defer.

### Baseline at initial review (repository facts)

- `package.json` pins Node `>=24`, pnpm `12.8.1`, Nuxt `4.5.2`, Nuxt UI `4.11.1`, Effect `4.0.0-rc.117`, TypeScript `6.0.3`, `vue-tsc` `3.3.11`, Vite `7.3.6`, Vitest `5.0.1`, Playwright `1.58.2`, and the other package versions shown in the review table below.
- CI uses Node 24 and the exact pnpm 12.8.1 pin; `Dockerfile` uses `node:24-bookworm-slim`. M21/ADR 0034 deliberately scoped the pnpm v12 upgrade without changing Node or app dependencies.
- The canonical `pnpm typecheck` is Nuxt/Vue typechecking. `typecheck:tsgo` is a separate native-preview check; its installed TypeScript 7 preview does not mean the `typescript` compiler dependency can replace the canonical check.
- Better Auth is configured for GitHub OAuth only, and ADR 0036 records one initial app instance on Coolify. There is no configured Magic Link or OAuth Proxy flow. A deployment during an in-flight OAuth callback may require restarting that sign-in.
- The current Vitest config uses `happy-dom` and `@vitejs/plugin-vue`; browser coverage uses Playwright. M0 records that `@nuxt/test-utils` was not used in the final test configuration after its attempted Nuxt transform path failed.

PR #4 was refreshed onto current `main`, kept `vue-tsc` at 3.3.11, passed the full hosted quality workflow, and was merged. The changelog/risk summary below remains as a record of what was accepted.

### Likely breakage points at a glance

- **#1 `pnpm/action-setup` v6:** action setup/pnpm resolution could regress, but the repository keeps its explicit pnpm `12.8.1` pin and CI passes.
- **#2 `actions/checkout` v7:** fork checkout is blocked for `pull_request_target`/`workflow_run`; this repository uses neither trigger. The current workflow passes.
- **#3 `actions/setup-node` v7:** the action's ESM implementation/cache handling could fail during workflow setup; Node 24 and the app runtime do not change. The manual rerun passes.
- **#5 Vite 8:** Rolldown replaces the esbuild/Rollup pipeline, so Vite plugins, config hooks, SSR/build output, or chunk behavior are the main compatibility risks. The isolated quality/build workflow passes.
- **#6 Effect 4 stable:** moving from an RC to the final v4 package can expose API/type/runtime changes; the current full quality job passes after a manual rerun. The first attempt's socket failure has no established Effect cause.
- **#4, #7, and #8:** PR #4's `vue-tsc` incompatibility and workaround are detailed below. Its `oxlint` update also adds one non-blocking `consistent-function-scoping` warning; baseline oxlint 1.83 reports none. #7 has a confirmed TypeScript/`vue-tsc` incompatibility; #8's Node 26 declarations can permit APIs not present in the Node 24 runtime, so defer.
