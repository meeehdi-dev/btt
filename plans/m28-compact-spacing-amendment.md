# M28 Amendment — Compact spacing refinement

> **Status:** Approved via Plannotator on 2026-10-06 and implemented. Final local verification passed, the final Plannotator live-app review returned no feedback, and the human declared M28 complete on 2026-10-06. ADRs 0042 and 0043 are accepted; M27 remains separate.

## Context

The approved M28 implementation harmonized app-authored spacing around Tailwind's 4px base, with examples including 24px page gutters, 16px card/form padding, and 12px compact-card padding. In the current conversation, the human reviewed the running Nxmr app at 1280+ CSS px and requested a materially denser result, including less padding around the bordered agenda filters, smaller vertical gaps between page sections, and matching horizontal/vertical page padding.

The Plannotator live-app annotations on the correct Nxmr `/today` route (overlay viewport: 2492×1282 CSS px) identified three concrete issues: (1) the filter wrapper renders `sm:p-6 p-2`, so Nuxt UI's responsive `sm:p-6` makes the desktop inset 24px despite the source's `p-2` override; (2) the Today page uses `space-y-6` (24px) between its main sections; and (3) the dashboard main uses `px-6 py-4`, giving unequal 24px horizontal and 16px vertical padding. This reveals that the previous source-class audit did not account for responsive defaults generated by Nuxt UI.

This amendment changes the former M28 spacing direction recorded in ADR 0042, which said to avoid 2px spacing. The human approved replacing only that spacing policy with this amendment; M28's desktop-only support target and behavior constraints remain unchanged. Implementation is authorized within the approved scope.

## Approved amended scope

- Re-audit every app-authored padding, margin, `gap`, and stack-spacing declaration in `app/**/*.vue`, `app/app.config.ts`, and application CSS; reduce spacing across the application rather than only the screenshot's filters.
- Use a compact 2px-based spacing scale (2, 4, 6, 8, 12, and 16px) and assign values by role. Do not mechanically halve classes: review each layout for hierarchy, readability, and function. Avoid app-authored 24px layout spacing unless a specific, reviewed composition requires it; document any exception.
- Compact role targets: 16px page inset and largest section separations; 8px standard app-authored card/form padding; 4px compact-card padding and related-control gaps; 2px padding inside border-only filter/toolbars and similarly tight utility surfaces. Reduce current spacing to these roles where feasible.
- **Human-requested live-app follow-up (2026-10-06):** use consistent 8px page-stack gaps around Today filters/agenda, reduce the Ticket Board filter-to-board gap to 8px, align the Agenda view group with the other 32px toolbar controls, keep end-of-visible-hours labels fully visible without changing time-grid geometry, and vertically center Settings. The human also directed that releases be marked done only on Release detail, not through project-card quick actions; ADR 0043 records that action-location decision.
- Set shared Nuxt UI card header/body/footer slots to compact 8px padding through the app theme config, replacing their generated responsive defaults (including `sm:p-6`). For Today/Week agenda and Ticket Board filter cards, explicitly override the shared body padding to 2px. Reduce inter-filter gaps where app-authored. Keep labels, icons, accessible names, and filter behavior.
- Reduce Today page section spacing from `space-y-6` to the approved compact role and change the dashboard main inset from `px-6 py-4` to an equal, smaller all-around inset (`p-4`). The app-level Nuxt UI card-slot override in `app/app.config.ts` replaces responsive default card padding with 8px; audit individual `UCard` body overrides to keep card-specific compact roles, including 2px filter surfaces.
- Keep the desktop-only 1280 CSS px support target, domain behavior, keyboard access, and useful board scrolling. Preserve the 1px `py-px` time-grid exception and all time-grid dimensions, pointer hit geometry, and duration mapping.
- Preserve Nuxt UI's intrinsic select-control sizing and usable pointer/keyboard hit targets, as chosen by the human via Plannotator.
- Do not change APIs, data, auth, dependencies, deployment, CI, Playwright policy, or workflow.

**Decision (human via Plannotator):** apply 2px to the bordered filter wrapper and spacing around the selects; preserve the Nuxt UI select trigger size and hit targets. This follows M25's approved direction that compactness comes from tighter surrounding spacing rather than smaller controls.

## Out of scope

- Changing agenda/ticket domain behavior, control labels, data, time-grid geometry, pointer hit areas, or keyboard semantics.
- Reintroducing responsive/mobile/touch layouts below 1280 CSS px.
- Changing Nuxt UI select-control sizing; the human chose to keep these controls at their standard size.
- Any CI, dependency, API, auth, schema, or deployment change.
