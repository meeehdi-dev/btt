# M7 — Search and compact UI polish

## Context

M6 is complete (`docs/milestones/m6-agenda-drag-blocks.md`). M7 retains universal search, keyboard/mobile polish and final empty/loading/error states, and adds the requested compact layout and page interactions. This plan was approved before implementation. The product roadmap is updated in `PLAN.md`; execution log: `docs/milestones/m7-search-and-ui-polish.md`.

## Approach

1. **Search:** Add a bounded, authenticated `/api/search?q=…` read endpoint for clients, projects, releases, tickets and time entries. Search names/titles and time-entry descriptions (plus associated ticket title for entries), trim/validate query length, escape SQL LIKE wildcards, return a small per-type limit with deterministic ordering and enough IDs/labels/date to navigate. Apply owner and active-ancestor/active-record visibility to each joined query; exclude archived records from ordinary search, and avoid fetching full entity lists client-side. Empty/too-short queries produce no results. Use existing `requireUserId` and Drizzle joins. Desktop top bar contains search; on mobile search lives inside the full-screen navigation menu. Debounced grouped results, clickable items, keyboard `/` or Ctrl/⌘K to focus, arrows/Enter to select, Escape to dismiss; don't steal keys from form fields. Time-entry hits navigate to `/today?date=YYYY-MM-DD` (Today must read/validate the query on load), with ticket name/date/time context in the result. Error/empty/loading states are explicit. No schema/dependency changes.
2. **Shell and compact pages:** Restructure `app/layouts/dashboard.vue` into desktop sidebar + top search + content. Default collapsed icon rail, expand/collapse button with an accessible name and localStorage-backed expanded preference (guard SSR). Main nav links retain labels via accessible names/tooltips when collapsed; user avatar/name and Settings at sidebar bottom, sign-out reachable from user menu. On mobile replace rail with a top-bar burger opening a full-viewport, keyboard-accessible menu with labeled navigation, search, Settings, account and sign-out; close via explicit button, Escape, route change; restore focus, prevent background scrolling while open. Keep the top bar compact and reduce page padding. Any spaced horizontal control/action row touched in M7 must become a true vertical column on mobile (not wrap into an uneven row), then space items across on wider screens. Remove decorative intro headings/descriptions on Today, list and Settings views, leaving accessible section labels, filters, actions and real empty/error messages. Keep compact entity identity/breadcrumb, relevant metadata and actions on detail/edit/create forms; remove only redundant descriptive copy there, not meaningful form titles/validation or navigation.
3. **Today:** Reuse current date/calendar/previous-next/today, workday progress and Add time entry modal; put date controls, unfiltered day progress and Add button in one spaced row on wider screens and a clearly ordered vertical column on mobile (date, progress, add; date's previous/calendar/next controls remain grouped together). Remove the Today Settings shortcut; Settings remains in nav. Keep progress sourced from all entries, not filters (ADR 0012); preserve mobile and drag behavior.
4. **Cards/board/Settings:** Make project grid and release/milestone cards whole-surface navigable while independent nested controls retain their actions. In ticket board, release ticket cards, and Today ticket-entry context, always expose relation and external-link icons that open popovers on hover/focus/click, even for one item. Every popover item is named/icon-labeled; related tickets are internal links preserving board highlight/locate when possible; external items are real `<a href>` links with native context menu and safe new-tab behavior. A top-right count badge overlays the icon only when the corresponding relation/link count is >1, and remains within trigger bounds to avoid clipping in overflow-constrained cards. Keep lane-based status, filters, drag and Settings behavior. Center Settings form.
5. **Polish and consistency audit (human-expanded scope):** Keep non-conflicting shortcuts. Audit all app buttons/actions and add a clear matching icon, with accessible names. Audit icon-only buttons currently relying on native `title` for tooltip feedback; replace those with Nuxt UI `UTooltip` while retaining meaningful `title` on truncated-content text. Apply an app-wide, focused list/card contrast pass using Nuxt UI semantic surfaces (`bg-muted`, `bg-elevated`) and semantic borders, not raw palette colors. Keep icon-trigger/count badge presentation consistent across ticket contexts, with counts contained within trigger bounds. Show tracked/estimate/usage on board and release cards, emphasizing tracked time with `text-primary` and muting estimates; distinguish Today’s worked duration from its target the same way. Keep the approved usage ratio bands. Check touched empty/loading/retry/error states and preserve board drag guard; no new mobile drag.

## Review-approved addition

Human confirmed the final code-review findings in chat: contain relation/external-link count overlays within their triggers; visually distinguish tracked time from estimates on release and ticket-board cards; make the same tracked-versus-target distinction in Today’s workday summary. Adding tracked usage to board cards expands the original approved scope; ADR 0019 records this approval and the resulting display rules.

## Boundaries

No auth policy, schema or deployment changes, no redesign of board status editing/agenda gestures. Human has approved the local icon dependency; do not add other dependencies. If search performance requires indexes or altered archival semantics, pause and seek explicit approval. The expanded-sidebar preference is local to the browser, not a database setting. Detail titles/breadcrumbs remain; search defaults to active records, with historical work still accessible through existing detail/Today history paths.
