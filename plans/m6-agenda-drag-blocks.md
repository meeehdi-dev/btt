# M6 — Agenda drag/drop time blocks

## Context

M5 is complete (`docs/milestones/m5-today-agenda.md`). The next roadmap milestone is M6: desktop drag creation in both directions, moving/resizing existing blocks, with non-drag mobile controls and mandatory ticket linkage. M4 already enforces 30-minute entries and non-overlap; M5 presents them on a configurable day timeline. `server/db/schema.ts` confirms **time entries have no archived flag**; only tickets/ancestors may be archived while their time remains visible/editable history. This plan is the reviewable M6 scope; implementation is not authorized until human approval. Human clarified that archived tickets/parents do not change whether their historical time entries can be dragged.

## Approach

- Extend Today, not the data model. Inspired by `../tt/app/pages/index.vue` + `components/day-slot.vue`, use a 30-minute slot origin and continuously update a temporary preview; unlike `tt`'s weekly grid, use pointer-coordinate gestures on the existing single-day timeline at the desktop (`md`) breakpoint, clamped to configured visible hours and midnight. Use explicit grab/resize affordances or a noninteractive card surface for moving; never steal link, badge or form clicks. Support start→end and end→start creation; keep the initial slot anchored, clamp the preview at the first occupied boundary (in either direction), and never jump over occupied blocks. Do not start a gesture on occupied space. Minimum preview is one slot; release opens the existing add modal prefilled with the selected start/duration, requiring an active ticket before POST. Cancel/Escape discards the preview.
- For existing entries, preserve duration while moving within the same visible-hour day. Permit a small edge-tolerance auto-placement: if the pointer-derived top of the proposed block overlaps an occupied block by only a few pixels, settle into the _adjacent free 30-minute-aligned slot on the approached side_, preserving duration (propose ≤12 CSS px, evaluated against raw pointer geometry before slot snap; never jump across a blocker or to a distant opening). Show that destination in the preview. If it cannot fit there, or the overlap exceeds tolerance, snap back and show an accessible error alert; a drop outside the permitted grid also snaps back. Unlike `tt`'s broad auto-reposition logic, do not relocate across an occupied block or silently leave a failed move unchanged. Resize from either edge, minimum 30 minutes, clamping to the closest neighbor, visible-window boundary or midnight. `tt`'s separate top/bottom grab strips suggest clear resize handles, but avoid its global mouse-up listener and DOM hiding/hit-testing; use scoped pointer capture and timeline geometry so release/cancel outside the card resets reliably. Use all fetched entries, not only rendered/filtered rows, for client-side occupancy; expose filtered-out entries as semitransparent blockers during any active create/move/resize gesture. PATCH only the changed start/duration, refresh after success; retain original and show the server error on concurrency/validation failure. Disable duplicate saves while pending, reset pointer state on cancel, day/filter/window change, unmount or breakpoint change.
- Historical entries linked to archived tickets or ancestors remain editable/movable; only new entries require active tickets. Keep drag desktop-only (ADR 0009/0010). Add a keyboard/mobile-accessible agenda edit action with a non-drag form for same-day start/duration correction; retain the existing ticket detail editor for date changes, out-of-window edits and deletion. Creation also remains possible via the existing Add time entry modal on any viewport. Visible hours are presentation only: entries outside stay discoverable in before/after lists; they are not draggable until within the visible timeline. Explain this near the agenda.
- Put pure slot/occupancy/clamping geometry in a testable utility (`app/utils/agenda-drag.ts` or `shared/` if existing interval helpers fit), rather than `tt`'s mutable global `useState` event/selection state. Separate committed server rows from previews; do not insert an unsaved empty-ID entry into the fetched list as `tt` does. Reuse `shared/time-entry.ts` for interval semantics and slot size; the API's transactional owner/overlap checks remain authoritative. No schema, dependency, or API contract change anticipated. Record the approved interaction policy in ADR 0014 and link it from the milestone file.

## Reuse

- `app/pages/today.vue` owns date/filter/settings state, entry data, add modal and refresh; `app/components/TodayAgenda.vue` renders the desktop timeline with `pixelsPerMinute = 2.25`, and mobile chronological entries. `TodayAgendaEntry.vue` renders ticket links, metadata and badge popovers; protect their interactions.
- `shared/time-entry.ts` exports `slotMinutes`, `validSlot`, and half-open `overlaps`; ADR 0011 requires one-day 30-minute aligned entries, serialized owner-scoped writes and no overlaps including archived history.
- `app/components/TicketTimeEntries.vue` — non-drag correction form on ticket detail (includes date, time, duration); `app/pages/today.vue` has an active-ticket modal for quick add, but no agenda-level edit action. `app/components/TodayAgendaEntry.vue` contains nested ticket links and badge popovers, so drag handles must avoid hijacking their clicks.
- `server/api/agenda/index.get.ts` returns **all** owned entries on the day plus full ticket/archival metadata and unfiltered total; use `entries` rather than `filtered` as collision occupancy, including hidden or archived-parent history. `server/api/time-entries/index.post.ts`, `[id].patch.ts`, `server/domain/time-entries.ts` — owner-scoped POST/PATCH already validate slots, lock owner row, reject collisions across all tickets including archived ones; PATCH preserves unmodified fields, permits historical correction on unchanged archived ticket.
- `tests/e2e/agenda.test.ts` — owner/settings/filters/mobile browser fixture and API creation; `tests/e2e/time-entries.test.ts` exercises collision/ownership. No new persistence schema is required for same-day manipulation.
- `../tt/app/pages/index.vue`, `../tt/app/components/day-slot.vue`, `../tt/app/components/event.vue`, `../tt/app/composables/use-events.ts`, `../tt/app/composables/use-long-press.ts`, `../tt/app/utils/index.ts` — **UX inspiration, not code to copy**: slot-origin bidirectional preview, distinct top/bottom resize handles, grab/move with a motion threshold, and per-day slot bounds. Caveats observed: `tt` checks creation overlap only on release (not while previewing), auto-shifts moves beside blockers even for substantial overlap (limit this to a few-pixel edge tolerance), mutates shared event state and relies on DOM visibility toggling plus document hit-testing to resolve resize position. Replace these with pure interval geometry, scoped pointer state and existing transactional POST/PATCH; do not add VueUse/dayjs or migrate its weekly view into M6.

## Decisions and open questions

- Decision (human, chat): retain 30-minute/no-overlap rules. Creating on a day clamps the preview at an existing entry boundary while pointer movement continues; creation does not jump over the blocker. Existing-entry drag/drop moves to another time slot; a few-pixel edge overlap should auto-place in the adjacent free slot, but substantial overlap still snaps back with an alert error (Plannotator feedback supersedes the earlier blanket snap-back rule). Resize clamps at a neighbor or midnight. During drag/create, show filtered-out entries semitransparently to explain blocked slots. Defer cross-day drag until the weekly view. Keep corrections via non-drag UI.
- Fact: `time_entry` has no archive operation/column (`server/db/schema.ts`); archiving tickets/parents does not archive their time. Existing PATCH permits time corrections against the same archived ticket (`server/domain/time-entries.ts`, ADR 0011). Desktop-only drag and non-drag alternatives are required by ADR 0009/0010.
- Decision (human, chat): historical time entries are unaffected by archival of associated tickets/parents; they remain draggable for corrections. Drag gestures are limited to the configured visible hours; use the non-drag editor outside them.
- Fact: native draggable full-card board implementation lives in `app/components/TicketBoardCard.vue`; pointer initiation on noninteractive surfaces is reusable, but minute-precision calendar gestures need pointer coordinates rather than HTML drop lane semantics. The current timeline clips an entry starting within and ending beyond visible hours; correctly render the clipped portion without changing stored duration.
- No unresolved product questions; implementation details such as exact visual handles and screen-reader wording may be refined in review within the approved interaction rules.
